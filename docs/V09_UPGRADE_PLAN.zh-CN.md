## 语言设置与来源规则

计划增加统一语言登记，前后端从同一份数据生成或读取代码、选项原名、文字脚本、Wiki 站点／中文变体与格式化回退。`docs/v0.9/locales.plan.json` 仅是设计输入，运行时不得自动加载或据此启用语言。

界面语言、内容语言、翻译目标继续分开：内容／翻译的“自动”跟随已生效界面语言；手动内容选择不改变界面、展签顺序或翻译目标。保存原有设置，不把翻译服务支持某语言等同于界面已经翻译。

自动模式按浏览器首选语言列表匹配已支持语言。地区变体归入相应界面语言，同时保留有效地区标签供日期、数字、排序和可用语音使用；中文先识别显式文字脚本，再识别地区，无法匹配时回退英文。前后端要使用同一套规范化规则。

| 界面设置 | 特殊国内来源排序 |
| --- | --- |
| 自动检测并规范化为简体中文 | 保留现有国内顺序 |
| 手动选择简体中文 | 使用国际顺序 |
| 自动繁中、英语或其他语言 | 使用国际顺序 |
| 手动繁中、英语或其他语言 | 使用国际顺序 |

国际顺序为目标语言 Wikipedia → 国际 Bing → Google 与其他来源。国内条件由界面自动检测状态决定，不能因单独选择中文正文就触发。图片入口沿用同一条件；实际服务失败与用户临时禁用仍应被尊重。

## Wiki 与缓存

每次只解析用户请求的语言：先以英文条目为身份锚点，读取目标语言关联；缺关联时，在目标语言独立检索并核对身份；无法确认目标页时回退英文。中文简繁共用中文站点身份，并保留各自正文变体。

身份核对优先使用明确的 Wikidata 身份及正式学名。混合香料、加工材料与原植物不能因关键词相同被认作同一实体；证据不足时返回未确认。运行时文章标题不能直接覆盖馆藏名称。

结果应区分：已找到目标语言、已确认缺页、网络／限流失败导致未确认、身份不符、正在展示已验证缓存。界面明确标注请求语言、实际语言、出处与回退原因；失败刷新可保留同语言同身份的已验证旧结果，不能把网络失败缓存为“没有此语言”。

语言关联映射可以继续缓存整张映射；目标语言独立检索、正文与翻译缓存需包含条目身份、来源、目标语言／变体及相关修订标识。切换语言或条目后，旧请求不得覆盖新结果。预取只覆盖当前选择，不对 18,379 条目并发请求十种语言。

## 名称、检索、字体与读音

- 展签左侧使用界面语言；英文界面右侧为中文，其他界面右侧为英文。标签使用具体语言名称。
- 常用名按语言保存值、核对状态、出处与核对时间。保留已审核中英文及所有用户编辑；缺少可靠名称时显示一次正式学名及缺失提示，不制造译名或重复两张相同学名展签。
- 学名、原文引用与来源标题保持可辨认的实际语言。界面翻译、正文翻译和已核对常用名是不同数据，不互相冒充。
- 目录与搜索支持这些语言的名称及别名，检查重音、组合字符、日／韩文与西里尔文字。排序采用相应语言规则；拼音继续服务中文，不用于所有语言。
- 字体显示原名字族加已登记的界面别名。默认回退按文字脚本选择；手动字体与现有设置继续可用。本机字体枚举仍需用户主动点击及浏览器授权，清单不上传。
- 英语读音、拼音与音标保留；新增语言按实际可用语音展示能力，不承诺每台设备都有十种语音，不自动下载字体或语音包。
- 长标签及窄分屏继续适配目录收起／恢复。保持明确的助手能力检测；Edge 手动分屏可用不等于扩展有自动接口，原生比例不能承诺自动设为 2∶1。
