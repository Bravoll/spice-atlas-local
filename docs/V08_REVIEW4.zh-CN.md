# v0.8 第四轮验收：分屏收回、Edge 状态与目录布局

程序仍为 0.8.0，构建 0.8-review4；助手为 0.8.2，消息协议为 2。本文记录发布前验收；用户于 2026-11-01 批准将该修订作为 v0.8 commit 并 push。

## 当前行为

- 根据真实接口检测自动分屏。当前 Edge 若未提供接口，明确显示“安装助手也无法自动唤醒”，隐藏无效的自动分屏按钮，保留直接打开原站的新标签链接。Edge 本身的手动分屏与扩展自动调用分开说明。未连接时按钮执行重新检测，不再只弹说明。
- Google／百度等受限来源使用助手创建的原站页；切换来源时复用该页。切回 Commons、Bing、可内嵌来源或阅读模式时，显式退出助手的原生分屏并关闭该来源页。原站区域另提供“关闭分屏”。
- 创建与关闭按图鉴标签串行执行。创建尚未完成就切回 Commons，也会在创建后收回。浏览器中手动关闭分屏会同步布局。只操作当前助手记录的配对，不关闭其他用户分屏或被移走的页面。
- 顶部新增“目录”按钮。普通桌面目录可拖动边缘调宽（190–420 像素），方向键微调，双击／Home 复位；普通布局选择保存在当前浏览器。
- 进入分屏默认收起目录；需要时可临时展开，退出后恢复普通布局。窄视窗的目录采用浮层，并可用 Escape 或遮罩收起。正文、名称、图集和顶栏随内容宽度重排。
- 当前公开 tabs 分屏接口没有比例控制参数，本助手不支持自动设置 2∶1；用户可拖动浏览器分隔线。不会通过改变整个浏览器窗口尺寸来代替分屏比例。

## 验证

- 227 项后端测试通过。
- 14 个界面／扩展套件共 190 项检查通过；本轮新增 18 项生命周期、Edge 不支持状态、目录调节及恢复用例。
- 使用实际应用、桥接与后台代码配合受控浏览器 API，验证 Google → Commons → 百度 → Bing 的创建、收回与布局恢复，以及慢创建后关闭、不误关其他分屏。
- Chrome 实际渲染检查：1363、960、720、480 像素 iframe 视窗，使用明确标记的合成正文和模拟分屏状态。960 视窗宽度／滚动宽度均为 960；720 和 480 视窗扣除竖滚动条后分别为 705／705、465／465，无横向溢出。720 浮层目录高度约 687 像素，拖动目录宽度从 252 改为 326 后，退出模拟分屏恢复为 326。
- 以上布局观察不能等同于安装助手后的真实 Windows 原生分屏实测。用户已反馈 Chrome 的上一轮助手可打开分屏；本轮助手的真实 Chrome／Edge 本机行为仍需设备验收。
- 新 ZIP 的启动与升级结果见 data/verification_v08.json。

## 更新及本机验收

1. 先退出旧分屏，再停止旧服务并原位更新。扩展重新加载后可能无法继续认定旧配对，故升级前先手动关闭旧分屏一次。
2. 在 Chrome／Edge 扩展卡片点击“重新加载”，确认版本 0.8.2，再对图鉴强制刷新。继续引用原安装目录中的 browser_helper。
3. Chrome 选择 Google／百度：应自动建立或复用右侧原站页。切回 Commons／Bing：应收回该页并恢复目录。
4. Edge 无自动接口时应显示明确说明及有效新标签链接，不出现只弹说明的“打开分屏”按钮。Edge 若实际提供接口，则按实际检测结果启用。
5. 检查顶部目录开关、边缘拖动、窄视窗浮层，以及返回后的原宽度／收起状态。需要 2∶1 时拖动浏览器自己的分隔线。
